# Project audit — 16 September 2026

The project is **not ready for unattended live operation**. Its basic asynchronous scheduler works, but model integration, stop controls, patch verification, security boundaries, and dashboard accuracy have substantial defects. Passing the existing unit tests does not establish that the advertised workflow works end to end.

This audit found **26 actionable findings: 16 P1 findings and 10 P2 findings**. P1 means a blocker for reliable unattended live use; P2 means a functional or operational defect that should follow the blockers. Runtime reproductions and code-review findings are distinguished below.

**Scope and evidence.** Reviewed every Python module, the TypeScript components, HTML/CSS, runner, package configuration, tests, workspace rules, and operating runbook. Executed the existing suite, frontend compilation, isolated backend/control/solver probes, headless Chromium interactions, a disposable wheel build, and public GitHub search requests. The probes use temporary state, local fixture repositories, and mocked GitHub/model writes. No comments, PRs, or model API requests were sent by the audit. Production application code was not changed.

**Are Antigravity models continuously working until the user stops them?**

The daemon repeats two Python workflows: inbox polling and a combined hunter/solver loop. Each AI operation is a separate, finite HTTP request. There is no ongoing Antigravity reasoning session, IDE inference bridge, Antigravity SDK integration, or tool-using model repair loop in the application. Reading a transcript's model label does not invoke that model.

All four AI operations call the same Gemini REST endpoint. Selecting Claude or GPT-OSS places that identifier into a Gemini request URL. Without a Gemini key, the engine returns heuristic decisions; its patch fallback produces no replacement code. At audit time, the workspace configuration had a GitHub token available and **no Gemini API key**. Consequently, the application's configured engine cannot perform live Gemini inference in that environment, and the fallback cannot autonomously repair source files.

The scheduler can keep polling while its process remains alive. This is different from continuously performing model inference or successfully solving issues. It deliberately sleeps between polls and pauses solving at its daily PR cap. The runner starts a foreground process and provides no supervisor, restart policy, process lock, or durable job queue. Closing its process or terminal, host sleep, a crash, or a fatal worker failure can interrupt service. No multi-hour endurance guarantee was established.

Google documents the IDE model selector as a conversation setting, sticky for the current user turn, and subject to model quotas. The [Antigravity model documentation](https://antigravity.google/docs/models) does not make this project's transcript reader an inference integration. Google's [SDK documentation](https://antigravity.google/docs/sdk/overview) describes an actual agent runtime; this repository does not use it. The [Gemini API reference](https://ai.google.dev/api/generate-content) describes the REST method this project actually calls.

**P1 findings — address before unattended live use.**

1. **A01 — Model selection is not provider integration.** Runtime routing capture sent `claude-sonnet-4.6` to `generativelanguage.googleapis.com/...:generateContent`. Missing keys, API failures, and malformed model output fall back to heuristics without establishing provider health. `ai_mode` is initialized from key presence, rather than successful inference. Sources: [ai_engine.py:72](</Users/jatinpandey/Antigravity/Github Agent/src/ai_engine.py:72>), [status_tracker.py:35](</Users/jatinpandey/Antigravity/Github Agent/src/status_tracker.py:35>). Add explicit provider adapters or an actual supported Antigravity runtime integration, validate capabilities, and expose real provider health and fallback status.

2. **A02 — Stop and Pause report success while execution continues.** Runtime probe observed two more inbox iterations after HTTP Pause and two more after `cmd_stop()`. CLI Stop only changes a status snapshot. Pause only changes `overall_status`; neither loop reads it. There is no dashboard stop/pause control wired to the orchestrator. Direct `stop()` and registered SIGINT/SIGTERM handlers do cancel asyncio workers. Sources: [cli.py:179](</Users/jatinpandey/Antigravity/Github Agent/src/cli.py:179>), [web_dashboard.py:123](</Users/jatinpandey/Antigravity/Github Agent/src/web_dashboard.py:123>), [orchestrator.py:85](</Users/jatinpandey/Antigravity/Github Agent/src/orchestrator.py:85>). Add a process-aware control channel, an execution pause gate, and an acknowledgement that comes from the running worker process.

3. **A03 — The solver never tests its applied patch.** Runtime fixture passed its baseline, received a patch that changed a tested value incorrectly, committed it, and reached mocked PR creation. Independently running the patched test failed. The pipeline ran tests once, before patch application, and also ignored `can_fix=false` and zero confidence. Source: [pr_solver.py:181](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:181>). Require reproduction, validated patch eligibility, tests after application, and verification of the exact commit being submitted.

4. **A04 — Missing or disabled verification counts as success.** Runtime fixture without a test configuration returned `(True, "No standard test runner configuration detected.")`. Disabling verification also returns success. The npm command explicitly permits no tests; generic directory detection can choose Python tests for a JavaScript, Go, or Rust repository containing a `tests` directory. Source: [pr_solver.py:346](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:346>). Fail closed when no meaningful test ran, resolve commands from actual project configuration, and require a regression test for the issue.

5. **A05 — Patch writes can escape the repository.** Runtime proof created a symlink in a disposable repository and used it as the patch target; a file outside the repository changed. `lstrip("./")` is not path containment validation, and internal traversal components are also unchecked. Source: [pr_solver.py:205](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:205>). Resolve paths, require containment, reject symlink targets and unsafe traversal, and restrict writable files.

6. **A06 — The claimed repository sandbox is a directory on the host.** Code review: cloned repository test scripts run under the current user with inherited environment, host filesystem access, network access, and available GitHub credentials/tools. Dry-run only suppresses GitHub writes; it still clones, runs arbitrary repository tests, edits files, and commits. Source: [pr_solver.py:61](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:61>). Use an actual isolated execution environment with bounded resources, restricted mounts/network, and no submission credentials available to repository code.

7. **A07 — Worker telemetry permits HTML/script injection.** Runtime Chromium proof inserted a harmless image error handler through `current_action`; it executed in the dashboard. Worker cards interpolate `worker.current_task` directly into `innerHTML`, and issue titles flow into this field. The CSP permits inline scripts. Sources: [workerCards.ts:78](</Users/jatinpandey/Antigravity/Github Agent/frontend/src/components/workerCards.ts:78>), [web_dashboard.py:303](</Users/jatinpandey/Antigravity/Github Agent/src/web_dashboard.py:303>). Render external strings with text nodes, validate links, and remove inline script permissions. Review task/toast interpolation at the same time.

8. **A08 — Local control endpoints accept untrusted-origin mutations.** Runtime HTTP proof sent a JSON body with `Content-Type: text/plain` and an external `Origin`; `/api/settings` accepted it and switched dry-run off. Controls have no Origin/Host validation, session authentication, or CSRF token. Loopback binding is a useful boundary but insufficient protection for sensitive local controls. Browser/network policies can limit particular cross-origin attacks; this audit establishes the missing server-side protection, not universal browser exploitability. Source: [web_dashboard.py:85](</Users/jatinpandey/Antigravity/Github Agent/src/web_dashboard.py:85>). Require authenticated control requests, permitted origins/hosts, correct content types, and explicit safe mode transitions.

9. **A09 — Live upstream contribution workflow is incomplete.** Code review: the solver clones upstream, pushes to upstream `origin`, and constructs a user-qualified head without creating or configuring a fork. A failed push does not prevent PR creation. Reused repositories are not fetched/reset to the current upstream base, and `checkout -B` starts from their current HEAD; earlier fixes can contaminate later branches. Several git command failures are unchecked. Source: [pr_solver.py:130](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:130>). Implement fork discovery/creation, separate remotes, fresh base checkouts/worktrees per issue, and checked git operations. Do not attempt a PR after a failed push.

10. **A10 — Patch generation lacks the evidence needed for precise repairs.** Code review: the prompt contains the issue and a short filename tree, without source contents, baseline failure details, or a reproduction. It requests an exact search snippet that the model has never read. Contributing guidelines are loaded into an unused variable; templates, DCO requirements, lint rules, and code-of-conduct instructions are not applied. There is no inspect/edit/test iteration. Sources: [ai_engine.py:237](</Users/jatinpandey/Antigravity/Github Agent/src/ai_engine.py:237>), [pr_solver.py:171](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:171>). Supply relevant source and instructions, reproduce first, and iterate against targeted verification before proposing submission.

11. **A11 — Discovery does not enforce the advertised eligibility rules.** Runtime fixture accepted an open PR as a bug issue and returned the same URL twice under different label queries. Query lacks `is:issue`, and no `pull_request` exclusion, in-pass deduplication, linked-PR check, repository-star lookup, or submission-time assignment recheck exists. Public API probe returned one open FastAPI issue without `stars`, but zero with `stars:>=1000`, despite the repository having more than 100,000 stars; this query does not satisfy the intended star-filter contract in that probe. [GitHub's issue search documentation](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests) explicitly distinguishes issues from PRs. Source: [issue_hunter.py:53](</Users/jatinpandey/Antigravity/Github Agent/src/issue_hunter.py:53>). Discover eligible repositories first or validate repository metadata, deduplicate, and recheck assignment/linked activity immediately before work/submission.

12. **A12 — Rate-limit and authentication failures can appear healthy.** Runtime mock of failed GitHub requests returned a fabricated `5000/5000` quota. Empty/error notification responses can appear as a clean inbox. The solver loop does not perform the inbox loop's quota check, search quota is not monitored independently, and exponential retries only exist on the REST path. When `gh` is installed, a CLI failure becomes a synthetic HTTP 500 rather than falling back to REST. Sources: [github_client.py:109](</Users/jatinpandey/Antigravity/Github Agent/src/github_client.py:109>), [github_client.py:167](</Users/jatinpandey/Antigravity/Github Agent/src/github_client.py:167>), [orchestrator.py:118](</Users/jatinpandey/Antigravity/Github Agent/src/orchestrator.py:118>). Preserve unknown/error states and HTTP metadata, monitor relevant quota buckets, and gate every worker on real authentication/quota health.

13. **A13 — Failed inbox actions are archived and recorded as completed.** Runtime fixture failed reply, read, and archive calls, yet attempted archival, persisted the thread as handled, and completed its task. “Mark all completed done” also fetches and archives notifications that were never handled. Fallback replies promise investigation without verified action and can engage discussions generically. Discussion context uses REST paths instead of a complete GraphQL read/comment workflow; its GraphQL comment fallback depends on a node ID fetched through that incomplete path. Sources: [inbox_manager.py:184](</Users/jatinpandey/Antigravity/Github Agent/src/inbox_manager.py:184>), [inbox_manager.py:211](</Users/jatinpandey/Antigravity/Github Agent/src/inbox_manager.py:211>), [github_client.py:275](</Users/jatinpandey/Antigravity/Github Agent/src/github_client.py:275>). 14. **A14 — Concurrent state writers lose history and weaken caps.** Runtime proof initialized two state stores, recorded a PR through the first, then handled a notification through the second. Reloaded state contained zero PR records. Atomic rename prevents partial JSON files; it does not coordinate stale read/modify/write snapshots. The standalone dashboard and CLI commands can create independent stores, and there is no single-instance daemon lock. Sources: [safety_guardrails.py:84](</Users/jatinpandey/Antigravity/Github Agent/src/safety_guardrails.py:84>), [web_dashboard.py:110](</Users/jatinpandey/Antigravity/Github Agent/src/web_dashboard.py:110>). Use transactional shared persistence and a single owner of execution, or robust cross-process locks plus reload/merge semantics.

15. **A15 — Simulation and failed attempts consume real eligibility state.** Runtime fixture recorded mock PRs in submission history; code review confirms the same paths mark issues handled in dry-run and on transient errors, empty patches, failed tests, or failed PR creation. Later live runs skip handled issues, and mock submissions count toward the rolling PR cap. Sources: [pr_solver.py:302](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:302>), [safety_guardrails.py:126](</Users/jatinpandey/Antigravity/Github Agent/src/safety_guardrails.py:126>). 16. **A16 — Cancellation does not reliably terminate child processes.** Runtime timeout proof left a Python child process alive; the audit explicitly terminated that fixture child afterward. `_run_command` times out/cancels `communicate` without terminating/reaping the process. Solver subprocesses run through `asyncio.to_thread(subprocess.run)`, whose execution is not stopped by cancellation of the awaiting coroutine. Interrupted solver tasks can remain `IN_PROGRESS` because cancellation bypasses their `except Exception` handler. Sources: [github_client.py:60](</Users/jatinpandey/Antigravity/Github Agent/src/github_client.py:60>), [pr_solver.py:138](</Users/jatinpandey/Antigravity/Github Agent/src/pr_solver.py:138>). Own process groups, terminate/kill/reap on cancellation, and finalize cancelled task records.

**What does work.** Both worker loops repeat in an isolated fixture and recover from an ordinary exception. The direct stop method interrupts interval waits and cancels asyncio tasks. Normal GitHub write methods respect dry-run in the exercised/modeled paths, and the solver aborts on a failing baseline or empty staged diff. Atomic JSON replacement protects against partial files. All five implemented desktop tabs initialize; task drawer open/Escape close, theme switching, and theme persistence worked. Frontend compilation and the small npm advisory check passed. These strengths are useful foundations, but they do not neutralize the live-operation blockers.

**Recommended repair sequence.** First establish a single execution owner with process-aware start/pause/stop, heartbeat health, transactional persistence, and controlled child-process cancellation. Next isolate repository execution and patch writes, remove HTML injection, protect local control endpoints, and separate simulation state from live state. Then implement real provider routing and a source-aware reproduce/edit/test loop with fail-closed verification and a correct fork/branch/push workflow. Finally unify API/persistence/frontend schemas, replace fabricated telemetry, repair settings/mobile/accessibility behavior, package frontend assets, and add CI.

Acceptance should require: a real supported provider call with accurately reported model/fallback health; repeated cycles under a defined soak-test duration; separate-process Stop and UI Pause preventing new work; no surviving child processes after shutdown; reproduction failing before a fix and passing afterward; PR submission blocked for failed/missing tests, failed pushes, assigned/linked issues, or unsafe paths; dry-run leaving live eligibility/caps unchanged; accurate task/log/worker rendering from backend records; correct settings error handling and restart persistence; and an installed-wheel/mobile browser smoke test.

**Limits.** No live provider call or external submission was authorized or needed for this audit. Provider routing was captured with a mock, not a paid API request. The public search probes were read-only and represent a point-in-time sample. No multi-hour soak, complete Python-version matrix, full accessibility conformance assessment, or comprehensive Python dependency vulnerability scan was performed. The short mocked scheduler stop measurement does not establish a real solver's shutdown latency. Security probes used harmless local fixtures and do not claim exploitation of the user's actual account.
